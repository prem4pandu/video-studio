## Top 10 limits

1. **One fixed card frame for every scene.** Classic: `.scene` with fixed padding and a `1fr / 200px` grid, 470px body (`src/composition.mjs:159`, template at `:289`). Film: absolutely positioned kicker / `h1` / workbench / guide at fixed pixel coordinates (`src/film.mjs:26`, template `:88`). Only the centre slot changes.
2. **13 of the 15 visual kinds are still pictures that fade in.** Only `base-ten` and `fraction-bars`-with-`equivalent` have multi-state animation (`src/composition.mjs:57-123`; `src/animation.mjs:38`; `src/partition.mjs:89`). `chart`, `clock`, `angle`, `coordinate-grid`, `area-grid`, `average-share`, `number-line` render final geometry directly.
3. **The default (film/quality) path has no scene-level camera move at all.** The classic path has a 1.5 % scale drift (`src/composition.mjs:299-301`); `fairFilmCompose` emits heading fade, the visual timeline, avatar poses and the pointer, and nothing on the scene root (`src/film.mjs:62-84`).
4. **No transition system.** Scenes are hard cuts on `data-start`; the only "transition" is a whoosh sound at each cut (`src/audio.mjs:107`). Intro/outro cards exist only in the classic renderer (`src/composition.mjs:253-277`, `:404-407`); the film renderer never imports `intro.mjs` (`src/film.mjs:1-8`) and the pipeline warns when the requested intro is dropped (`src/pipeline.mjs:158`).
5. **Reveal timing is entrance-based, not narration-anchored, for most elements.** The generic reveal is `scene.start + 0.25 + i * min(2, …)` (`src/composition.mjs:321-324`) with fixed 0.35s / 12px fades; quality reveals are word-count proportions, not semantic anchors (`src/quality-storyboard.mjs:3-12`).
6. **Question scenes are text-first, and the answer UI is mostly absent.** For a question, `visualHtml` returns only the narration paragraph — except when the (otherwise hidden) visual is a fraction `recap`, whose items are promoted to A/B/C option cards (`src/composition.mjs:58-59`). Interaction cards and the answer strip are built only in the classic renderer (`:282-288`); the default film path has no feedback step, no per-option timing, and text-only questions for every non-fraction kind (`src/film.mjs:51`).
7. **Non-maths lessons collapse to a numbered text list.** The only fallback is `.teaching-steps` (`src/composition.mjs:123`), and the planner may only choose the 15 enumerated kinds (`src/plan.mjs:47-63`, prompt list `:388-401`). There is no illustration/icon/photo primitive in the default path; generative footage is a ≤5s silent establishing shot in the open-source route only (`src/open-render.mjs:73-87`).
8. **Typography is fixed and duplicated across two coordinate systems.** 1280×720 authoring scaled `1.5×` (`src/composition.mjs:167`, `src/film.mjs:26`) versus native 1920×1080 quality overrides (`src/film.mjs:28`); hard-coded px sizes (`45/36/55px`), no type scale, and `Nunito` is referenced without any `@font-face` (`src/film.mjs:26`).
9. **Motion grammar is uniform and short.** Almost every entrance is `power3.out` at 0.30–0.45s; stamps use `back.out`; there is no anticipation, no overlap/staging, no per-distance duration, and no custom easing beyond GSAP presets (`src/composition.mjs:298-400`; `src/partition.mjs:102-170`).
10. **Verification cannot see what the picture means.** `teachingMetrics` only parses tween statements whose time argument is a literal number (`tools/teaching-metrics.mjs:24-35`), so quality-mode forEach reveals are invisible (verified by running the parser); `motionMetrics` is frame-difference only (`:139-178`); no `*.motion.json` sidecars are generated by the pipeline; pacing/motion gates emit warnings, not failures (`src/pipeline.mjs:160-161`).

## 1. Render architecture

### 1.1 Call chain (verified)

```
brief ──normalizeBrief──▶ plan.mjs: briefSchema                      (src/plan.mjs:64-76)
     ──generateLesson──▶ lesson JSON (scenes[].visual = 15-kind union) (src/plan.mjs:47-63)
     ──validateLesson──▶ arithmetic + visual constraints              (src/plan.mjs:242-369)
     ▼
fairRunPipeline ─▶ fairRenderLesson                                   (src/pipeline.mjs:17,55)
     ├─ fairNarrate(lesson) ─▶ per-scene WAV + phrases + words + envelope (src/pipeline.mjs:69)
     ├─ fairCompose(lesson, tracks, brief, projectDir)                (src/pipeline.mjs:71)
     │    ├─ film branch?  ──▶ fairFilmCompose                        (src/composition.mjs:246)
     │    └─ classic branch ▶ single index.html + GSAP timeline       (src/composition.mjs:407)
     ├─ hyperframes check  project --json                             (src/pipeline.mjs:80)
     ├─ hyperframes render project --fps 30 --quality looks --strict  (src/pipeline.mjs:89)
     ├─ ffmpeg: music/SFX mix, `-c:v copy` (picture never re-encoded) (src/pipeline.mjs:104; src/audio.mjs:232)
     ├─ ffprobe + volumedetect + contact sheet                        (src/pipeline.mjs:113-123)
     └─ teachingMetrics(project) + motionMetrics(mp4)                 (src/pipeline.mjs:127-128)
```

`fairCompose` immediately delegates to `fairFilmCompose` when **any** of these is true
(`src/composition.mjs:246`): `brief.generationVersion === 'quality'`, the lesson contains a `base-ten` visual,
or `brief.avatar === 'none'`. Server defaults are `generationVersion: 'quality'` and `avatar: 'none'`
(`src/server.mjs:128`), so the **classic renderer is now an exception**: it requires `classic` mode *and*
a non-`none` avatar *and* no base-ten scene (e.g. the authored fraction benchmark, `scripts/fraction-phase-a.mjs:19-22`).

`generationVersion: 'open-source'` bypasses both and renders Manim through `fairRenderOpenLesson`
(`src/pipeline.mjs:62-65`; `src/open-render.mjs:51`; `scripts/manim-scene.py:197`).

### 1.4 One template, many centre panels

- **Classic** emits exactly one layout: header (`FAIR / CLASSROOM`, audience) → eyebrow + `h1` → `.visual` slot → footer; optional 200px presenter column (`src/composition.mjs:289`). The 14 non-base-ten kinds are HTML strings inserted into `.visual` by a single if/else chain (`:57-123`); base-ten lessons never take this route (`:246`).
- **Film** emits one layout: kicker + scene count + `h1` + workbench card + `fallback`/`animation` + optional guide + lesson mark (`src/film.mjs:88`). Variants are the `closeup` (base-ten discovery only, `discovery.mjs:132`), `question-shot`, `no-guide` and `quality-film` classes (`film.mjs:88`), plus a few beat-colour rules (`film.mjs:28`).
- There is **no archetype object/registry**; "archetype" is `visual.kind` plus whichever builder the if/else reaches (`composition.mjs:57-123`).

**Inference.** The pipeline has high *diagram* coverage and low *cinematography* coverage: the design unit is
"scene = title + one diagram", not "shot". Nothing in the composer can frame, reframe, cut within a scene,
layer foreground/background, or hold on a detail.

### 2.3 What actually changes state

Only three builders mutate a model: `fairBaseTenState` (`src/base-ten.mjs:4-18`, conserved quantities), the
partition engine (one persistent rectangle, geometry derived from `n/d`, `partition.mjs:22-42`), and the
discovery counter (counts actual cubes, `discovery.mjs:71-104`). Everything else renders a *final* picture;
"animation" is the entrance. **Inference:** this is why the videos read as narrated slides: the visual does
not have to be watched to be understood, because it never withholds and then reveals information.

The open-source route is a **third vocabulary**, not a reuse of these builders: Manim draws text, rectangles
and arrows for `place-value`, `equation`, `comparison`, `number-line`, `steps`, `recap` and `base-ten`
(`scripts/manim-scene.py:22-177`; whitelist `src/open-render.mjs:12`), and Wan can contribute a silent ≤5s
establishing clip (`src/open-render.mjs:73-87`). Its only animated diagram is also base-ten
(`scripts/manim-scene.py:92-138`); other kinds are `add`ed fully formed (`:217`). So any new archetype must
be implemented once for HyperFrames and (if desired) again for Manim.

## 3. Hard limits & anti-patterns

### 3.1 Layout: fixed card, fixed zones, fixed reading order

- Classic reserves the same zones on every scene: 32/52/112px padding, 470px body, 200px presenter
  (`src/composition.mjs:159`), plus header/footer chrome (`:289`). The title sits above the visual in every
  beat, so a "hook" and a "recap" have identical hierarchy.
- Film hard-codes every element position: `h1` at 62/69, workbench 40/143/932×426, guide 943/286, lesson mark
  64/601 (`src/film.mjs:26`); quality mode re-hard-codes a second set: h1 154/164, workbench 220/286 1480×600,
  guide 1480/540 (`:28`).
- Both renderers are 16:9 only (`data-width="1920" data-height="1080"`; `composition.mjs:407`), though the
  composition root supports arbitrary sizes (`node_modules/hyperframes/dist/docs/compositions.md`).

**Inference.** No layout can express hierarchy through scale, asymmetry, full-bleed, or silence. The frame is
a worksheet, and the diagram is a figure placed on it.

### 3.2 Text density: the default is still a slide

- Every classic scene shows eyebrow, title, visual label, visual, footer, plus a caption repeating the
  narration (`composition.mjs:289,292`). Diagrams add their own text: place value prints two labels per column
  (`:64`), equations one line each (`:66`), the fallback up to four numbered paragraphs (`:123`).
- The fallback for both `steps` and `recap` is a numbered paragraph list (`composition.mjs:123`); film hides
  the step numbers but keeps the paragraphs (`film.mjs:26`: `.line-number,.step-number{display:none}`).
- A `question` without options — every question in the film path unless its visual is a fraction `recap`, and
  every classic question without an interaction — is a single paragraph at 28/34px (`composition.mjs:59`) or
  46px (quality, `film.mjs:28`); the learner must hold the task in memory while answering.

### 3.3 Timing: measured scene length, entrance-based internals

- Scene duration is `max(4, narration + pause + 0.7)` (`composition.mjs:261`; `film.mjs:44`). That makes the
  *scene* narration-driven but ignores visual complexity: a 999-block bundling and a two-line equation get the
  same budget for the same narration.
- Lead is fixed at 0.35s before speech (`composition.mjs:260`; `film.mjs:44`); tail adds 0.7s of nothing.
- Generic reveals: `scene.start + 0.25 + i*min(2, speech/(items+1))` (`composition.mjs:323`) — a fixed cadence
  capped at 2s, unrelated to what the voice is saying. Only `steps`/`recap`/choices use phrase anchors
  (`itemRevealTimes`, `:218-227`).
- Phrase anchoring is fractional when no phrase is close: `phraseAt(fraction)` snaps to the nearest phrase
  within 0.45s else returns `speechStart + duration*fraction` (`composition.mjs:308-313`). The partition engine
  uses six such fractions (`partition.mjs:94-99`); the fraction-equivalence fragments use
  0.26/0.45/0.72/0.88/0.92 (`composition.mjs:340-342,354-355`) and the fraction-comparison fragments use
  0.2/0.38/0.58/0.76/0.9 (`composition.mjs:358`).
- Quality **reveals** are word-proportional, not semantic: target word index
  `floor((i+0.35)/count * words.length)`, clamped to `[0.45, 0.35+duration-0.2]`
  (`quality-storyboard.mjs:3-12`). A single-element visual is anchored ~35% into the word list; with N elements
  the last lands near `(N-0.65)/N`, capped 0.2s before the scene ends.
- The strongest anchoring in the codebase is base-ten: three authored spoken beats compile to exact word
  offsets, then to word timestamps (`plan.mjs:151-168`; `animation.mjs:6-16`), with a documented fallback to
  proportional placement when the transcript does not match (`animation.mjs:12-15`).

**Inference.** Timing is "narration-shaped" at the scene level and "animation-shaped" only for base-ten,
partition, and choice cards. For 13 kinds, when the reveal happens is a function of element count, not meaning.

### 3.4 Camera, depth, transitions

- Camera moves in the whole system: classic scene push `scale 1.004→1.019, y 1→-2` over the full scene
  (`composition.mjs:299-301`); partition camera `scale 1→1.04, y 0→-8` then a 1.3s settle
  (`partition.mjs:160-162`); avatar float/breath (`composition.mjs:393-396`); quality pointer slide
  (`film.mjs:83`). That is the complete list.
- No pan, tilt, dolly, rack focus, parallax, depth layers, foreground occlusion, or per-shot framing. Layers
  are flat siblings: background set (`.sun/.floor/.shelf`, `film.mjs:26`), workbench card, content, guide.
  Quality mode *deletes* the background set (`.quality-film .sun,.quality-film .floor,.quality-film .shelf{display:none}`,
  `film.mjs:28`), leaving a yellow dotted wall and a white sheet. The `closeup` and `question-shot` classes only
  reposition the same fixed elements (`film.mjs:26`); they are layout presets, not camera moves.
- `production-plan.mjs` defines a camera vocabulary — `shotSize` establishing…insert and
  `movement` static/push-in/pull-out/pan-left/pan-right/track (`src/production-plan.mjs:42-45`), plus timed
  `overlays` (`:11-17`) — but the module is **unused**: no import exists outside its own file (grep over `src`,
  `scripts`, `tools`, `test`, `public`).
- Transitions: none. Scenes butt against each other; the only cross-scene signal is the whoosh at cuts
  (`audio.mjs:107`). Intro/outro are not transitions but extra clips, and only in classic.

**Inference.** With one 1.5% push and hard cuts, the video has no visual rhythm separate from the voice. Beat
changes are audible (sfx) but not visible.

### 3.5 Easing and motion grammar

- Entrances: `{opacity:0,y:12}→{opacity:1,y:0}, 0.35s, power3.out` (`composition.mjs:323`); `h1` 0.3s/10px
  (`:298`); quality fallback 0.42s + `blur(5px)` + `power4.out` (`film.mjs:64`). Exits are almost non-existent:
  the intro card is the only scene-like element that fades out (`intro.mjs:52`); lesson scenes hard-cut.
- Stamps: `back.out(1.2–2.2)` (e.g. `composition.mjs:347,352`; `partition.mjs:137,150`); pulses are
  `sine.inOut` with `yoyo/repeat:1`.
- Durations do not scale with distance or element size. Movement inside base-ten is
  `moveDuration = min(1.5, gap*0.55)` (`animation.mjs:43`); partition cuts space at `min(0.8, 1.5/n)`
  (`partition.mjs:120`). These are the only two adaptive engines.
- No overlap/offset discipline across independent elements beyond per-index stagger; no anticipation; no
  settle/follow-through other than `back.out`.

### 3.6 Dead time and frozen frames

- Classic: after the last reveal (often ~0.9 of the scene) only the imperceptible push continues
  (`composition.mjs:301`); plus 0.7s tail. Film: after the last quality reveal (≤ `duration-0.2`) there is
  nothing but the pointer's final fade and, for `mira`, occasional pose swaps (`film.mjs:78`).
- `motionMetrics` defines "frozen" as <0.05 mean frame difference and "ambient" as 0.05–0.5
  (`tools/teaching-metrics.mjs:171-175`). A 1.5% push is likely *ambient*, i.e. it counts as "not frozen"
  without being a teaching change. Measured on the one rendered Manim lesson:
  76s, 65.7% of frames still (`stillFramePercent`), 18% of seconds frozen, 4 ambient seconds, 76% visible
  (`node tools/teaching-metrics.mjs --video .fair-video/cfa9525f-…/project/lesson.mp4 --json`) — the frozen
  gate (>10%) fails. That render is the open-source/Manim route, but it demonstrates that the metric's bar is
  already near the current output.
- **Inference.** The pipeline's own gates tolerate a picture that changes only at scene boundaries; the goal
  "a visible change every ~4–6s of narration" is not enforced anywhere.

### 3.7 One-size-fits-all durations and density

- All diagrams share the same entrance duration and the same scene tail; density adaptation is limited to
  block/unit size (`animation.mjs:45`, `discovery.mjs:32`), area-grid cell size (`composition.mjs:80`) and
  chart bar width (`composition.mjs:105`).
- At high density, base-ten compresses motion into the cue gap: `staggerBudget ≤ 0.4s` for an arbitrary number
  of blocks (`animation.mjs:43,61`); 999/ones groups can bundle ~99 blocks with `0.4s` of total stagger.
  Discovery caps reveal/finish at `min(1.25, phase*0.45)` (`discovery.mjs:53`).

### 3.8 Typography

- Sizes: classic `h1` 45px, steps 25px, caption 25px, place digit 62px (`composition.mjs:159`); film `h1`
  36px (`film.mjs:26`) and caption 34px (`film.mjs:95`); quality `h1` 55px, prompt 46px, digit 112px (`film.mjs:28`). All px,
  no scale, no tokens.
- The only text fitting is a character-count ternary for the question prompt
  (`narration.length > 180 ? 28 : 34`, `composition.mjs:59`) and `overflow-wrap:anywhere` on titles/equations
  (`composition.mjs:159`), which can break maths mid-token.
- `font-family:Nunito,system-ui,sans-serif` (`film.mjs:26`) with no font file or `@font-face` anywhere in
  `src/public/scripts`; renders as the platform UI font.

### 3.9 Question / pause design

- `question` visuals are deliberately hidden as diagrams (`plan.mjs:411`), with one exception: a fraction
  `recap` visual is promoted into A/B/C option cards by `visualHtml` itself (`composition.mjs:58`).
  `fairQuestionCard` upgrades one further sentence pattern to a numeral visual (`question-card.mjs:21-26`).
- Film path has no interaction contract and no answer feedback: options appear only through that fraction-recap
  branch; everything else is the prompt plus pause bar (`film.mjs:51,79,88`). Classic adds interaction cards and
  an answer strip only when `fairInteractionFor` returned something (`composition.mjs:282-288`), and derivation
  is fraction-only: it needs a fraction `recap` question and a `fraction-bars` answer (`interaction.mjs:56-64`),
  otherwise explicit interactions only (`:55`).
- `interaction.waitSeconds` is clamped 3–15s (`interaction.mjs:33`) and never checked against narration length.
- Pauses are `pauseSeconds` + 0.7s tail, and the pause card appears exactly at speech end
  (`composition.mjs:397-400`; `film.mjs:79`).

### 3.10 Correctness / state bugs that are also visual-quality bugs

- **Fraction partition can annotate `×1`.** `fairFractionModel` sets `factor = target.d % source.d === 0 ? … : null`
  (`partition.mjs:30`) and the SVG prints `×${model.factor ?? 1}` (`partition.mjs:81`). Validation accepts any
  truly equivalent pair (`plan.mjs:288-296`), so `2/4 = 3/6` renders a mathematically wrong `×1` scaling badge
  (confirmed by calling `fairPartitionSvg('2/4','3/6')`: both scaling texts are `×1`), and the non-partition
  path silently drops the transformation note because `fractionTransformation` requires equal integer factors
  (`composition.mjs:50-51`).
- **Interaction cards lose their diagram for non-fraction options**: `fractionTrack` returns `''` unless the
  label matches `n/d` (`composition.mjs:39-41`), while `interactionCardsHtml` always calls it
  (`:233`). A base-ten or decimal question with an explicit interaction shows letters + text only.
- **Two base-ten renderers diverge.** `<100` or `place !== 'hundreds'` routes to `discovery.mjs`
  (`animation.mjs:40`), everything else to `animation.mjs`. Palette, geometry, typography and even the
  equation wording differ (`discovery.mjs:122-130` vs `animation.mjs:85-89`). The same `visual` can look like
  two different products depending on the number.
- **Beat labels are duplicated three times** with different wording: `composition.mjs:229`, `film.mjs:30`,
  and an inline map in `film.mjs:86`.

### 3.11 Accessibility / robustness

- SVGs carry `role="img"` + `aria-label` in most builders (e.g. `composition.mjs:45,64,71`; `partition.mjs:63`),
  and captions/transcript are emitted (`composition.mjs:409-410`).
- `prefers-reduced-motion` only disables CSS animations (`composition.mjs:159`; `film.mjs:28`); the GSAP
  timeline is unaffected, so reduced-motion users still get every tween. The quality pointer is the only
  element hidden (`film.mjs:28`).
- `data-track-index` misuse (audio on 2, captions on 3, pauses on 4) is harmless but misleading, per the
  library's own docs (`node_modules/hyperframes/dist/docs/data-attributes.md`).

## 4. Coupling to school subjects

### 4.1 Domain map

| Kind | Subject | Hard constraint | Text or picture? |
|---|---|---|---|
| `base-ten` | whole-number place value | 1–999, ones/tens/hundreds, 5 modes (`plan.mjs:54`, `:402`) | Animated objects |
| `fraction-bars` | fractions | n 1–24, d 2–12, equivalent must be truly equal (`plan.mjs:288-296`) | Bar + optional partition |
| `place-value` | decimals/place value | ≤8 digits, named column (`plan.mjs:48`) | Static grid |
| `number-line` | order, rounding | min<max, mark in range (`plan.mjs:287`) | Static axis |
| `area-grid` | fractions/percent/decimals | ≤10×10, shaded ≤ cells (`plan.mjs:57`) | Static cells |
| `angle` | geometry | 10–350° (`:58`) | Static SVG |
| `coordinate-grid` | geometry/algebra | 0–10, unique points (`:59`) | Static SVG |
| `chart` | statistics | 2–8 non-negative items (`:60`) | Static chart |
| `average-share` | mean/average | 3–6 items, 0–12, mean 0–12 (`:61`) | Static board |
| `clock` | time | hour 1–12, minute 0–59 (`:62`) | Static face |
| `bar-model` | part-whole word problems | 2–6 parts (`:56`) | Static boxes |
| `comparison` | any comparable pair | free text (`:50`) | Static panels |
| `equation` | any | ≤4 lines (`:49`) | Text |
| `steps` / `recap` | any | ≤4 items (`:52-53`) | Text |
| `question` (beat, not kind) | any | narration only (`plan.mjs:411`) | Text |

All 15 kinds are built for mathematics; `steps`/`recap` are the only domain-neutral ones and they are text-only.
There is no primitive for: process/cycle, timeline, map, label-the-diagram, sort/classify, cause→effect,
character dialogue, code, or any illustrative scene.

### 4.2 What a non-maths lesson gets

- The planner prompt enumerates only the 15 kinds (`plan.mjs:388-401`); the JSON schema enforces the same set
  (`plan.mjs:112-126`). A history or science lesson must therefore pick `steps`/`recap`/`equation`/`comparison`,
  i.e. **headline + numbered text** (`composition.mjs:123`), plus captions and the presenter (only when an
  avatar is explicitly chosen; default is `none`, `plan.mjs:71`).
- Quality mode adds a domain gate in the other direction: a place-value topic is *required* to contain a
  base-ten visual, and "generic diagram fallback is not allowed" (`plan.mjs:343-345`). So the system is strict
  inside its one domain and silently generic outside it.
- The only non-diagram imagery is the open-source Wan establishing shot (≤5s, silent, no text
  `open-render.mjs:73,85`) and the avatar sprite/SVG. The film path copies only `pip-sprites.png`
  (`film.mjs:39`).

### 4.3 Is there a registry?

No. Dispatch is an if/else chain (`composition.mjs:57-123`) plus a single `kind === 'base-ten'` check in film
(`film.mjs:50`). Adding a kind touches **six** places:

1. zod union — `plan.mjs:47-63`
2. constrained-decoding JSON schema — `plan.mjs:112-126`
3. prompt enumeration + rules — `plan.mjs:388-401`
4. classic HTML builder — `composition.mjs:57-123`
5. film animation dispatch (if it needs motion) — `film.mjs:50-57`
6. open-source whitelist (if supported) — `open-render.mjs:12`

Validation constraints live in `validateLesson` (`plan.mjs:242-369`; visual checks `:287-317`); metrics read
`scene.visual.kind` (`tools/teaching-metrics.mjs:99`). **Inference:** the absence of a registry is the main reason the visual
vocabulary has grown wide (15 kinds) but shallow (2 animated engines) — each kind is a one-off string builder.

### 5.2 The specific blind spots

- **Meaning:** no check that the diagram's numbers equal the narration's, except `mathClaims` arithmetic on
  the lesson JSON (`plan.mjs:318`) — it never looks at the rendered SVG. The `×1` partition bug above passes
  every check.
- **Motion intent:** HyperFrames supports `*.motion.json` assertions (`appearsBy`, `before`, `staysInFrame`,
  `keepsMoving`). The pipeline emits none; only a hand-authored script does (`scripts/blueprint-test.mjs:213-214`).
- **Coverage:** `check`'s default 9 samples across a 3–5 minute lesson means many scenes are never inspected;
  static-sweep failures are per composition, not per scene.
- **Pacing gates are advisory:** failed gates become strings in `quality-report.json` (`pipeline.mjs:160-161`);
  only the `checks[]` list can fail the run (`:177`), and none of the visual checks are in it except the
  quality metadata assertions (`:140-152`), which assert *bookkeeping* (`qualityProof` booleans), not pixels.
- **No golden frames / visual diff:** the bundled CLI exposes `snapshot`, `compare` and `grade-compare`
  (`node_modules/hyperframes/dist/skills/hyperframes-cli/SKILL.md:164`; `…/references/lint-validate-inspect.md`),
  but the pipeline never captures frames for regression.

**Inference.** A regression that turns every diagram into a grey box, or reveals every element at t=0, would
pass the pipeline as long as audio, durations, captions and contrast still pass (and the static-sweep does not
trip). The quality proof is a proof about *event metadata*, not about the frame.

### 6.1 A minimal beat-driven contract (concrete)

The pieces already exist; they are just not generalised:

1. **Author the speech as beats, not a paragraph.** Base-ten already requires `narration:null` +
   exactly three `spokenBeats`, compiled to cue word offsets (`plan.mjs:26-46`, `:402`) and timed by
   `fairCueTimes` (`animation.mjs:6-16`). Extend the same shape to every animated kind:
   `beats: [{text, cue}]`, with the composer compiling cue words → word timestamps once.
2. **Builders return phases, not code.** Partition already names them: `showAt, cutAt, countAt,
   shadeCountAt, invariantAt, equalAt` (`partition.mjs:171`). Require every animated kind to return named
   phases + an `invariant` description; that is enough to (a) place sound cues (`sfxCues` →
   `pipeline.mjs:98-101`), (b) write `motion.json` assertions, (c) prove "the screen changed on the phrase".
3. **Emit semantic targets into the HTML.** `data-cue="cut-1"`, `data-cue="count-3"`, `data-invariant="shade-end"`.
   Today only positional `data-quality-target` is injected at runtime for fallback reveals (`film.mjs:64`).
4. **Serialize ops.** Replace `code` strings with `ops[]` at the four return sites (row 6 above); the same
   array feeds GSAP, `teachingMetrics`, the quality report, and a `motion.json` emitter. This alone fixes the
   parser blind spot verified in §5.

### 6.2 Where a new *visual archetype* plugs in with minimum blast radius

Highest-leverage single change: **make `film.mjs:50` dispatch through a registry instead of
`kind === 'base-ten'`**, and make every registry entry return the partition-style
`{html, ops, cues, phases, proof}`. Then a new archetype is one file + one schema entry + one prompt line.
Everything downstream (`composition.mjs` classic adapter, quality events, sfx, metrics, motion sidecars) can
consume the same object. Without that, any new animated visual is invisible in the default quality path and
receives one whole-card fade (`film.mjs:52,64`).

### 6.3 Suggested order (inference)

1. **Ops + metrics** (rows 6, 11): makes every later change measurable.
2. **Camera/transition + layout variants** (rows 7, 8): removes the "slide deck" ceiling without new content.
3. **Question visuals + beat contract** (rows 5, 10): the pedagogical weak point.
4. **Registry + one non-maths archetype** (rows 1–3): proves the system is not fraction-specific.

## 7. Bottom line

The instructional control system is real and unusually careful: scene durations come from measured audio,
base-ten quantities are conserved by construction, partitioning never resizes the shade, question/answer
isolation is enforced and tested, and sound cues can be emitted from the renderer. The visual layer is much
weaker than the pedagogy it carries: one card layout, 13 static diagram kinds, two animated engines, no
transitions, one ambient push (and none in the default path), uniform 0.35s fades, a text-first question beat,
and verification that measures container metadata, DOM tween counts and pixel motion but never the meaning of
the picture.

The cheapest path to materially better learning videos is not more visual kinds. It is (a) a structured
timeline so motion can be measured, (b) a beat/cue contract generalised from base-ten and partition, (c)
camera + layout variants so the frame can express emphasis, and (d) question visuals so the learner is not
asked to answer from memory of a paragraph.
